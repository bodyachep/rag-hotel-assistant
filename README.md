# RAG HOTEL ASSISTANT
## Інтелектуальний AI-асистент для пошуку та бронювання готелів

**Тип проєкту:** Full-stack AI Application  
**Основна технологія:** Retrieval-Augmented Generation (RAG)  
**Мовна модель:** Qwen 3  
**Frontend:** React + Vite  
**Backend:** Python  
**Майбутні платформи:** Вебсайт + Telegram-бот  
**Репозиторій:** GitHub

---

# 1. Ідея проєкту

RAG Hotel Assistant — це інтелектуальна система для пошуку готелів, яка дозволяє користувачам спілкуватися зі штучним інтелектом звичайною людською мовою та отримувати результати відповідно до своїх потреб.

Основна ідея полягає в тому, щоб користувачеві не потрібно було самостійно переглядати сотні готелів, відкривати десятки сторінок і вручну перевіряти характеристики.

Замість цього він може написати:

- «Знайди готель в Одесі з укриттям і акумулятором».
- «Потрібен готель до 3000 грн за ніч, мінімум 4 зірки».
- «Знайди готель з генератором, але без акумулятора».
- «Покажи готелі, у яких генератор не вказано».
- «Потрібен готель із паркінгом, опаленням і можливістю проживання з тваринами».
- «Знайди готель на першому або другому поверсі».

AI має зрозуміти намір користувача, визначити всі вимоги, застосувати точні фільтри до бази даних і сформувати зрозумілу відповідь.

Головна мета — створити повноцінного AI-асистента, а не просто звичайний пошуковий фільтр.

# 2. Як працює система

Основою проєкту є архітектура RAG (Retrieval-Augmented Generation).

Передбачений принцип роботи:

1. Користувач вводить запит природною мовою.
2. Система аналізує текст і визначає вимоги.
3. Python-модуль розпізнає місто, ціну, кількість зірок, послуги та інші характеристики.
4. Застосовуються точні структуровані фільтри.
5. RAG-механізм допомагає знайти релевантні записи в базі знань.
6. Результати передаються мовній моделі Qwen 3.
7. AI формує відповідь людською мовою.
8. Frontend відображає результати у вигляді красивих карток готелів.

Важливий принцип: мовна модель не повинна самостійно вигадувати характеристики готелів. Фактичні дані беруться з бази.

# 3. Поточна Python-частина

Python-частина вже має основу системи пошуку.

Реалізовано:

- Завантаження інформації з Excel.
- Створення векторного індексу.
- Індексацію 140 готелів.
- Пошук готелів.
- Розпізнавання параметрів із текстового запиту.
- Фільтрацію за містом.
- Фільтрацію за ціною.
- Фільтрацію за кількістю зірок.
- Фільтрацію за послугами.
- Формування текстових карток готелів.

Є функція `filter_hotels(question, index)`, яка відповідає за розпізнавання параметрів та відбір готелів.

Є функція `format_hotels(hotels)`, яка формує зрозумілий результат пошуку.

# 4. Система фільтрів

Одна з найважливіших частин проєкту — точна система розпізнавання вимог користувача.

Передбачені такі категорії.

**Основні характеристики:**
- Місто.
- Максимальна ціна за ніч.
- Мінімальна кількість зірок.
- Тип готелю.
- Тип номера.
- Відстань до центру.

**Послуги:**
- Wi-Fi.
- Басейн.
- Сніданок.
- Паркінг.
- Кондиціонер.
- SPA.
- Ресторан.
- Дозвіл на проживання з тваринами.

**Важливі умови проживання:**
- Наявність укриття.
- Опалення.
- Генератор.
- Акумулятор.
- Поверх розташування номера.

Особлива увага приділяється логіці заперечень.

Наприклад:

«Знайди готель з генератором, але без акумулятора».

Система повинна зрозуміти:
- Генератор = Так.
- Акумулятор = Ні.

Також підтримується розрізнення трьох станів:
- Так.
- Ні.
- Не вказано.

Це особливо важливо для запитів на кшталт:

«Знайди готелі, у яких генератор не вказано».

Такий запит не повинен трактуватися як пошук готелів без генератора.

# 5. Робота з базою даних

На початковому етапі інформація про готелі зберігається в Excel.

У подальшому планується перехід до постійної бази даних, яка дозволить:

- Зберігати інформацію про готелі.
- Зберігати фотографії.
- Додавати нові готелі.
- Редагувати характеристики.
- Зберігати історію пошуків.
- Зберігати інформацію про бронювання.
- Відстежувати статуси бронювань.
- Керувати даними через адміністративну панель.

База повинна бути доступною не тільки локально, а й через розгорнутий сервер, щоб користувачі сайту та Telegram-бота працювали з одними даними.

# 6. Майбутня система бронювання

Окремий напрям розвитку — реалізація бронювання готелів.

Планується створити систему, у якій користувач зможе:

- Переглянути готель.
- Переглянути фотографії.
- Ознайомитися з характеристиками.
- Обрати дати заїзду та виїзду.
- Вказати кількість гостей.
- Створити бронювання.
- Переглянути свої бронювання.
- Скасувати бронювання відповідно до правил системи.

Для кожного бронювання потрібно зберігати:

- Ідентифікатор бронювання.
- Користувача.
- Готель.
- Дати проживання.
- Кількість гостей.
- Вартість.
- Статус бронювання.

Можливі статуси:
- Очікує підтвердження.
- Підтверджено.
- Скасовано.
- Завершено.

Важливо: потрібно передбачити перевірку доступності номерів, щоб не допускати подвійного бронювання.

Модель буде підключена до Python-бекенду через відповідний спосіб інференсу.
